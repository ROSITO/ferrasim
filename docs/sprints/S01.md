# S01 — Modèle et contrats d’entrée

Lancé le 14 octobre 2026. Statut : implémenté, vérifications locales et multi-plateformes en cours.

## Livrables

- Modèle Rust typé et sérialisable : version, unités, groupes, matériaux, affectations, prescriptions, charges, analyse, solveur et sorties.
- Contrat JSON exact `0.1`, champs inconnus et clés répétées rejetés ; erreurs structurées.
- Contrôle des valeurs finies, paramètres, doublons, références, affectations exhaustives et prescriptions contradictoires sur un même groupe.
- Chargement source-relatif et sérialisation avec validation préalable.
- [Exemple minimal](../../examples/minimal/model.json), [contrat documenté](../MODEL-FORMAT.md), [JSON Schema](../../schemas/model-0.1.schema.json) et programme Rust d’inspection.
- Tests de contrat, fichiers Unicode/espaces/CRLF et validation structurelle indépendante en Python.
- [ADR 0002](../decisions/0002-model-contract.md) et dépendances de vérification isolées dans un venv.

## Preuves

Sur macOS ARM64, Rust 1.96.0 : 17 tests de contrat S01 et le test CLI de S00 passent ; Clippy sans avertissement, compilation release, documentation sans avertissement, contrôle documentaire et validation JSON Schema indépendante passent également. L’exemple d’inspection charge le modèle minimal et résout son chemin de maillage. CI Windows/macOS/Linux à confirmer après push.

## Périmètre et critères de sortie

Le modèle minimal doit se charger et se sérialiser sans perte ; entrées invalides et versions inconnues doivent produire les catégories d’erreur prévues ; les checks passent sur les trois systèmes.

La validation S01 concerne le contrat et ses références déclarées. Le maillage n’est pas importé ; groupes réellement vides, nœuds absents, prescriptions sur groupes chevauchants et solvabilité demandent S02/S04/S05. Les validations scientifiques restent planifiées. Aucune nouvelle formulation constitutive ou FEM n’est livrée ici.
