## Vérifications

Contrôles locaux passés sur macOS ARM64, Rust 1.96.0 : formatage, compilation de développement, Clippy sans avertissement, test d’entrée CLI, build release, documentation Rust avec avertissements interdits, registre de validation et liens documentaires. Aide et version de la CLI exécutées avec succès.

Un clone neuf du dépôt distant, avec un nouveau répertoire de build, a compilé via `cargo check --workspace --locked` et passé le contrôle des documents/registre. Le cache partagé de téléchargements Cargo était présent : ce test vérifie un checkout et un build propres, pas une installation hors ligne ni un système totalement vierge.

La [CI de référence](https://github.com/ROSITO/ferrasim/actions/runs/38627233253), sur commit `9266339d5e4ce47aecc6384e57518850fb6bcf69`, a passé tous les contrôles sur Linux, macOS et Windows : formatage, Clippy, tests, release, documentation et registre/liens. Les actions GitHub sont fixées aux commits des releases examinées. Ces résultats qualifient les fondations compilables, pas des capacités physiques.

La première exécution a identifié une lecture dépendante de l’encodage Windows dans le script Python. La lecture UTF-8 explicite l’a corrigée ; les exécutions suivantes passent. Le rapport final est un changement documentaire vérifié localement, sans nouvelle modification de code ou de workflow.

Le test CLI vérifie qu’une commande `solve` non implémentée retourne une erreur. Les bibliothèques ne possèdent pas encore de formulation ; zéro test scientifique exécuté en S00.

## Réestimation et points ouverts

La baseline S00–S11 à deux semaines par sprint reste une hypothèse de travail pour deux développeurs et une revue numérique disponible. L’exécution accélérée de la préparation S00 ne constitue pas une mesure de productivité pour S03–S10 et ne justifie pas de raccourcir automatiquement le calendrier.

La capacité réelle n’est pas connue : aucune équipe ni disponibilité de référent scientifique n’est confirmée. Le planning calendaire reste donc non engagé. À S03, réestimer à partir des problèmes effectivement rencontrés sur TET4 et des résultats de revue ; à S09/S10, prévoir le temps d’obtention des références et de la comparaison externe.

Les décisions restantes et leurs échéances par porte de sprint figurent dans l’[ADR](../decisions/0001-foundations.md). Le responsable projet doit désigner la personne de revue scientifique ; elle ne doit pas être confondue avec l’auteur de la formulation.

## Critère de clôture

Le workspace et les contrôles de fondations peuvent être acceptés sur leurs résultats techniques. Le critère de sortie S00 de la roadmap inclut la revue du protocole ; aucune revue humaine indépendante n’est présumée réalisée. Les conventions sont proposées pour S01 et doivent être revues avant qualification scientifique S03.
